# アーキテクチャと責任境界

このリポジトリでは文字起こしのコア実装を共有しますが、外部から見える責任と実行環境を3つに分けます。

| 実行単位 | 種類 | 責任 | 責任を持たないもの |
| --- | --- | --- | --- |
| `scribe-bot` | Cloud Run Service | Slack・Discordイベントの受付、応答 | Web APIのジョブ管理、結果配信 |
| `scribe-api` | Cloud Run Service | サービス間認証、入力検証、ジョブ状態・結果API、Worker起動 | メディア処理、文字起こし本体、Botイベント |
| `scribe-transcription-worker` | Cloud Run Job | メディア取得、文字起こし、任意の要約、結果保存 | 外部HTTP API、Bot応答 |

コードは同じコンテナイメージを使いますが、エントリーポイント、環境変数、割り当てリソース、IAM境界を分けてデプロイします。API と Worker にはそれぞれ専用サービスアカウントを割り当て、API はジョブ状態の読み書き・結果の読み取り・Worker起動、Workerはジョブ状態と結果の書き込み・文字起こし用シークレット参照だけを行います。Bot用のSlack・DiscordシークレットはAPIとWorkerへ渡しません。

```text
外部サービス
    │ IAM認証付きHTTP
    ▼
scribe-api ── Firestore（ジョブ状態）
    │
    ├── Cloud Run Jobs API ──▶ scribe-transcription-worker
    │                              │
    └── Cloud Storage ◀────────────┘（完成結果）

Slack / Discord ──▶ scribe-bot ──▶ 共通の文字起こしコア
```

## API側の責任

`scribe-api` はジョブを受け付け、状態遷移と結果へのアクセスを提供します。クライアントとのHTTP接続を維持したり、クライアントの画面状態を管理したりはしません。呼び出し元は返された `jobId` を保存し、必要なタイミングで状態を再取得します。

APIが受け付ける入力は、既存アダプターが扱えるHTTPS URLです。ファイルアップロード、任意URLへのアクセス、利用者向け画面は責任範囲に含めません。

## Worker側の責任

Workerは1つのジョブだけを処理します。ジョブのリースを取得し、入力メディアをダウンロードして文字起こしし、結果をCloud Storageへ保存して終了します。再試行の可否や外部向けHTTP応答はAPI側が管理します。

## コード共有の方針

別リポジトリには分割しません。文字起こしコアと各サービスアダプターの変更を一度に検証できる利点を残しつつ、デプロイ単位で責任を分けます。将来、APIとBotでリリース周期や管理主体が大きく異なる状態になった場合に、初めてパッケージまたはリポジトリ分割を検討します。
